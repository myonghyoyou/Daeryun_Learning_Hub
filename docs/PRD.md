## 1. 개요 및 목표

### 1.1 배경
사내 각 부서가 자체적으로 업무/교육 문제를 등록하고, 전 직원이 자유롭게 문제를 풀며 학습할 수 있는 사내 문제 은행 서비스가 필요하다. 관리자는 문제를 등록·관리하고 문제별 정답률 등 통계를 통해 문제 품질과 직원 학습 현황을 파악할 수 있어야 한다.

### 1.2 목표
- 부서 관리자가 자기 부서 명의로 문제를 등록·관리할 수 있는 관리자 화면 제공
- 전 직원이 PC/모바일에서 자유롭게 문제를 풀 수 있는 학습(연습) 화면 제공
- 문제별 정답률/오답률을 중심으로 한 통계 제공
- PC와 모바일에서 로그인 후 진입하는 화면을 기기별로 다르게 분기

### 1.3 비목표 (Goals가 아닌 것)
- 정식 시험/평가(응시기간, 제한시간, 부정행위 방지 등)는 다루지 않는다 (섹션 10 참고)
- 서술형 문제의 수동 채점 워크플로우는 다루지 않는다

### 1.4 용어 정의
| 용어 | 정의 |
|---|---|
| 총괄 관리자 (Super Admin) | 전사 모든 부서의 문제/통계를 조회·관리할 수 있는 최상위 관리자 |
| 부서 관리자 (Dept Admin) | 자기 소속 부서 명의로 등록한 문제만 관리할 수 있는 관리자 |
| 직원 (Employee) | 문제 풀이만 가능한 일반 사용자 |
| 출제 부서 | 문제를 등록한 관리자의 소속 부서 (문제의 "소유자" 개념이며, 풀이 접근권한과는 무관) |
| 시도 (Attempt) | 직원이 문제 1건에 대해 답을 제출한 기록 |

## 2. 사용자 역할 및 권한

### 2.1 역할 정의
| 역할 | 설명 | 관리자 화면 접근 | 문제 풀이 화면 접근 |
|---|---|---|---|
| 총괄 관리자 | 전사 전 부서의 문제/통계를 조회·관리 | 전체 부서 데이터 접근 (PC만) | 가능 |
| 부서 관리자 | 자기 부서가 등록한 문제만 관리 | 자기 부서 데이터만 접근 (PC만) | 가능 |
| 직원 | 일반 사용자 | 접근 불가 | 가능 (PC/모바일) |

### 2.2 권한 매트릭스
| 기능 | 총괄 관리자 | 부서 관리자 | 직원 |
|---|---|---|---|
| 문제 등록/수정/삭제 (전체 부서) | O | X (자기 부서만) | X |
| 문제 등록/수정/삭제 (자기 부서) | O | O | X |
| 타 부서 문제 조회 (관리 목적) | O | X | - |
| 통계 조회 (전체 부서) | O | X | X |
| 통계 조회 (자기 부서) | O | O | X |
| 부서/계정 관리 (직원 계정 생성, 부서 생성 등) | O | X | X |
| 문제 풀이 (전사 공통 문제) | O | O | O |
| 본인 풀이 이력 조회 | O | O | O |

> 문제는 어느 부서가 등록하든 **전사 직원 공통으로 노출**된다. "자기 부서만"이라는 제약은 어디까지나 **관리(등록/수정/삭제/통계 조회) 권한 범위**에 한정되며, 풀이 대상 범위와는 무관하다.

## 3. 인증 및 로그인 흐름

### 3.1 계정 시스템
- 자체 계정 시스템(ID/PW)을 구축한다. 외부 SSO/AD 연동은 하지 않는다 (섹션 10 향후 확장 참고).
- 로그인 식별자는 **사번**으로 확정한다.
- 비밀번호는 해시(bcrypt 등)로 저장하며 평문 저장을 금지한다.
- 직원 계정은 관리자(총괄 관리자 또는 부서 관리자)가 생성하며, 별도의 공개 회원가입 화면은 제공하지 않는다.
- 계정에는 회사 이메일을 필수로 등록하며, 임시 비밀번호는 해당 회사 이메일로 전달한다.
- 최초 로그인 시 비밀번호 변경을 강제한다 (임시 비밀번호 발급 방식).

### 3.2 기기 판별 및 라우팅 규칙
로그인 화면 자체는 PC/모바일 반응형으로 동일 코드베이스에서 제공하되, **로그인 성공 이후 진입 화면은 기기 유형에 따라 분기**한다. 기기 유형은 반응형 브레이크포인트(뷰포트 너비) 기준으로 판별한다.

| 기기 | 역할 | 로그인 후 랜딩 화면 | 접근 가능 화면 |
|---|---|---|---|
| PC (데스크톱 뷰포트) | 총괄 관리자 / 부서 관리자 | 관리자 대시보드 | 관리자 화면 + 문제 풀이 화면 (양쪽 다 접근 가능, 화면 내 메뉴로 이동) |
| PC (데스크톱 뷰포트) | 직원 | 문제 풀이 화면 | 문제 풀이 화면만 (관리자 화면 메뉴 자체 비노출, 접근 시도 시 403) |
| 모바일 (모바일 뷰포트) | 전 역할 공통 (총괄 관리자/부서 관리자 포함) | 문제 풀이 화면 | 문제 풀이 화면만 (관리자 화면 라우트/메뉴 전체 비노출) |

핵심 규칙:
1. **모바일에서는 역할과 무관하게 관리자 화면에 접근할 수 없다.** 관리자 계정으로 모바일에서 로그인해도 문제 풀이 화면으로만 진입한다.
2. **PC에서는 역할에 따라 접근 범위가 달라진다.** 관리자 역할은 관리자 화면과 문제 풀이 화면을 모두 이용할 수 있고, 직원 역할은 문제 풀이 화면만 이용할 수 있다.
3. 뷰포트가 중간에 리사이즈되어 모바일↔PC 경계를 넘나드는 경우(예: 브라우저 창 크기 조절), 관리자 화면은 PC 폭 기준 미만에서 강제로 접근이 차단된다 (반응형 레이아웃이 아닌 접근 자체 차단).

### 3.3 세션/보안
- 인증 방식은 **서버 세션(Session Cookie) 기반**으로 확정한다. 로그인 성공 시 서버가 세션을 생성하고, 세션 식별자를 `httpOnly`, `SameSite=Lax` 쿠키로 클라이언트에 내려준다 (`trend_one/backend`와 동일한 방식).
- 일정 시간(예: 90분) 무활동 시 세션이 자동 만료되도록 타임아웃을 설정한다.
- 로그아웃 시 서버 세션을 즉시 무효화한다.
- 5회 이상 로그인 실패 시 일정 시간 계정 잠금 (무차별 대입 공격 방지).

## 4. 문제 은행 관리 (관리자 화면)

### 4.1 문제 유형
| 유형 | 설명 | 채점 방식 |
|---|---|---|
| 객관식 - 단일 선택 | 보기 중 정답 1개 선택 (보기 최대 5개) | 자동 채점 |
| 객관식 - 다중 선택 | 보기 중 정답 복수 선택 (보기 최대 5개) | 자동 채점 (선택 집합 완전 일치) |
| OX | 참/거짓 판단 | 자동 채점 |
| 주관식 (단답형) | 짧은 텍스트 입력, 정답과 문자열 비교 | 자동 채점 (공백/대소문자 무시 등 정규화 후 비교) |
| 빈칸 채우기 (멀티 blank) | 문제 본문에 여러 개의 빈칸 후보를 미리 정의해두고, 실제 출제 시 그중 일부를 무작위로 선택해 정답을 입력하도록 함 | 자동 채점 (섹션 4.1.1, 6.3 참고) |

> 서술형(자유 서술, 수동 채점 필요) 문제 유형은 본 서비스 범위에서 제외한다 (섹션 10).

### 4.1.1 빈칸 채우기 문제 상세 규칙
- 문제 등록 시 본문에 빈칸 후보 위치를 여러 곳(예: `{{blank_1}}`, `{{blank_2}}`, `{{blank_3}}` ...) 정의하고, 각 빈칸 후보별 정답을 개별 등록한다.
- 문제 단위로 "출제 시 노출할 빈칸 개수"(예: 정의된 5개 중 2개)를 관리자가 설정한다.
- 직원이 문제를 풀 때마다(시도 1건마다) 정의된 빈칸 후보 중 설정된 개수만큼 **무작위로 선택**하여 실제 입력 가능한 빈칸으로 노출하고, 선택되지 않은 나머지 빈칸 후보는 정답 텍스트를 그대로 노출한다(문맥 제공용).
- 따라서 동일한 문제라도 시도할 때마다 실제로 채워야 하는 빈칸의 위치/조합이 달라질 수 있다.
- 채점: 해당 시도에서 노출된 빈칸 전부를 맞혀야 그 시도가 "정답"으로 처리된다 (빈칸별 정오답 결과는 개별로도 저장하여 상세 피드백에 활용).

### 4.2 문제 등록 방식
1. **개별 입력**: 관리자가 화면에서 문제 1건씩 직접 입력/수정. 필드: 문제 유형, 문제 내용(텍스트 + 이미지 파일 업로드(선택, 업로드 완료 후 저장된 URL을 문제에 연결) + 참조용 지문(선택)), 보기(객관식/OX, 최대 5개), 정답, 해설(선택), 태그(선택). 빈칸 채우기 유형은 본문 내 빈칸 후보 정의, 각 빈칸 정답, 출제 시 노출할 빈칸 개수를 추가로 입력한다 (섹션 4.1.1 참고).
2. **엑셀 일괄 업로드**: 정해진 템플릿 양식의 엑셀 파일을 업로드하여 다건 등록.
    - 템플릿 컬럼(안): `문제유형 | 문제내용 | 이미지 | 참조지문 | 보기1 | 보기2 | 보기3 | 보기4 | 보기5 | 정답 | 해설 | 태그`
     - 문제내용: 문제 자체 텍스트 (빈칸 채우기의 경우 `{{blank_n}}` 마커 포함)
     - 이미지: 문제에 첨부할 이미지(선택). 이미지는 별도로 서버에 업로드하여 저장된 URL을 셀에 입력하는 방식으로 처리한다 (파일 업로드 후 URL 저장 방식으로 확정, 상세 UX는 섹션 11 참고)
     - 참조지문: 문제 풀이에 참고가 필요한 지문/본문이 있는 경우 입력(선택)
      - 보기1~보기5: 객관식/OX 문제의 보기, 최대 5개까지 지원(유형에 따라 일부 컬럼은 비워둠)
      - 태그: 여러 태그를 콤마로 구분하여 입력(선택)
   - 빈칸 채우기 유형은 빈칸별 정답과 출제 개수 설정이 다른 유형보다 복잡하므로, 엑셀 템플릿에 전용 컬럼 구성을 별도로 정의하거나 개별 입력만 지원하는 방식을 검토한다 (섹션 11 오픈 이슈 참고).
   - 업로드 시 행 단위 유효성 검증(필수값 누락, 유형별 정답 형식 오류 등) 후 성공/실패 건수와 실패 사유를 업로드 결과 화면에 표시한다.
   - 실패한 행은 등록되지 않으며, 성공한 행만 반영한다 (부분 성공 허용).
    - 업로드 이력(파일명, 업로드자, 업로드 일시, 성공/실패 건수)은 DB에 저장한다. 조회 화면과 다운로드 파일 형식은 실제 템플릿 확정 후 별도로 결정한다.

### 4.3 문제 관리 기능
- 문제 목록 조회 (필터: 유형, 상태(활성/보관), 등록일 범위, 태그, 키워드 검색)
- 문제 수정 / 삭제 (삭제는 소프트 삭제 - 상태를 "보관"으로 변경, 기존 풀이 이력 데이터 보존)
- 부서 관리자는 **자기 부서가 등록한 문제만** 목록에 노출되고 수정/삭제 가능
- 총괄 관리자는 전체 부서 문제를 부서별로 필터링하여 조회/관리 가능
- 문제에는 태그를 여러 개 지정할 수 있으며, 태그로 문제를 필터링할 수 있다.

### 4.4 부서/계정 관리 (총괄 관리자 전용)
- 부서 생성/수정/비활성화
- 부서 관리자 계정 생성 및 부서 배정
- 직원 계정 생성/수정/비활성화 (회사 이메일 필수, 개별 등록 + 엑셀 일괄 등록 지원)
- 계정 엑셀 템플릿 컬럼: `사번 | 이름 | 회사이메일 | 부서코드 | 역할`
- 계정 생성 시 임시 비밀번호는 등록된 회사 이메일로 전달하며, 최초 로그인 후 변경을 강제한다.

## 5. 통계 / 리포트 (관리자 화면)

### 5.1 핵심 지표 (MVP 우선순위 1)
- **문제별 정답률/오답률**: 문제 목록에서 각 문제의 누적 시도 수, 정답 수, 정답률(%)을 조회
- 정답률이 낮은(오답률이 높은) 문제를 상위에 정렬하여 "품질 검토가 필요한 문제"를 관리자가 쉽게 파악

### 5.2 조회 범위
- 부서 관리자: 자기 부서가 등록한 문제에 대한 통계만 조회 가능
- 총괄 관리자: 전체 부서 문제 통계 조회 가능, 부서별 필터링 가능

### 5.3 상세 화면 구성
- 문제별 통계 목록: 문제 내용(요약) / 유형 / 총 시도 수 / 정답 수 / 정답률 / 최근 시도일
- 문제 클릭 시 상세: 보기별 선택 분포(객관식의 경우 어떤 오답을 많이 선택했는지), 최근 오답 제출 샘플

### 5.4 향후 확장 지표 (MVP 이후, 섹션 10 참고)
- 개인별 성적/정답률 추이
- 부서별 비교 통계
- 응시율/미응시자 현황
- 기간별(주간/월간) 추이

> 부정행위 방지 방안(예: 문제/보기 순서 셔플, 응시 로그 모니터링, 재접속 제한 등)이 확보되면, 정규 시험(응시기간/제한시간이 있는 정식 평가) 기능을 향후 확장 범위로 재검토할 수 있다 (섹션 10 참고).

## 6. 문제 풀이 화면 (사용자 화면)

### 6.1 풀이 모드
- **자유 연습/복습 모드**로 동작한다. 응시 기간, 제한 시간, 1회성 정식 시험 개념은 없다.
- 직원은 언제든 원하는 문제를 반복해서 풀 수 있다.

### 6.2 화면 흐름
1. 문제 풀이 화면 진입 시 문제 목록(또는 카테고리/태그별 목록)을 보여준다.
2. 문제를 선택하면 문제 상세(보기 포함)를 보여주고 답을 제출한다.
3. 제출 즉시 정답 여부를 채점하여 결과(정답/오답, 정답, 해설)를 보여준다.
4. 직원의 풀이 기록(시도)은 모두 저장되어 본인 이력 조회 및 관리자 통계 집계에 사용된다.

### 6.3 채점 로직
| 유형 | 채점 규칙 |
|---|---|
| 객관식 단일 선택 | 선택한 보기가 정답 보기와 일치하면 정답 |
| 객관식 다중 선택 | 선택한 보기 집합이 정답 보기 집합과 완전히 일치하면 정답 |
| OX | 선택값이 정답과 일치하면 정답 |
| 주관식 단답형 | 제출 텍스트를 정규화(trim, 대소문자 무시, 공백 정리) 후 정답과 일치하면 정답. 정답에 복수 허용 표기(예: 콤마 구분 동의어)가 있으면 하나라도 일치 시 정답 |
| 빈칸 채우기 | 해당 시도에서 무작위로 노출된 빈칸 각각에 대해 제출 답안을 정규화 후 그 빈칸의 정답과 비교. **노출된 빈칸을 모두 맞혀야** 해당 시도가 정답으로 처리되며, 빈칸별 정오답 결과도 개별로 저장한다 (섹션 4.1.1 참고) |

### 6.4 본인 이력
- 직원은 본인이 푼 문제의 이력(시도 일시, 정답 여부, 제출 답안)을 조회할 수 있다.

## 7. 모바일 반응형 동작 규칙

- 프론트엔드는 React + Vite + Tailwind 기반 반응형 웹으로, PC/모바일이 동일 코드베이스를 사용한다.
- 프론트엔드 폴더 구조 및 아키텍처 컨벤션은 트렌드원 프론트엔드(`trend_one/frontend`)를 참고한다: `pages/`, `components/ui/`, `contexts/`, `hooks/`, `api/`(공통 API 클라이언트 + 도메인별 API 모듈), `routers/`(`PrivateRoute`/`PublicRoute`/`routes.jsx` 기반 인증 라우트 가드), `constants/`, `utils/`, `styles/` 패턴을 따른다. 본 서비스의 PC/모바일 분기 및 역할 기반 접근 제어(섹션 3.2)는 이 `PrivateRoute`/`PublicRoute` 가드 패턴에 기기(디바이스) 유형 체크 로직을 추가하는 형태로 구현한다.
- 라우팅 레벨에서 기기 유형(뷰포트 기준)을 판별하여, 모바일 뷰포트에서는 관리자 관련 라우트(`/admin/*` 등)로 직접 URL 접근을 시도해도 문제 풀이 화면으로 리다이렉트한다.
- 관리자 화면 자체는 데스크톱 레이아웃(넓은 표, 다단 필터, 엑셀 업로드 UI 등)을 전제로 설계하며, 모바일 최적화 레이아웃은 별도로 만들지 않는다 (섹션 9 비기능 요구사항 참고).
- 문제 풀이 화면은 PC와 모바일 모두에서 사용되므로 반드시 반응형으로 설계한다.

## 8. 데이터 모델 개요 및 기술 스택 제안

> 본 섹션은 PRD 수준의 개념 데이터 모델과 기술 스택 제안이며, 상세 스키마/아키텍처는 별도 기술 설계 문서에서 확정한다.

### 8.1 개념 데이터 모델

**Department (부서)**
- id, name(부서명), code(부서코드), status(활성/비활성), created_at

**User (사용자)**
- id, employee_no(사번), name, email(회사 이메일), password_hash, department_id(FK), role(SUPER_ADMIN / DEPT_ADMIN / EMPLOYEE), status(활성/비활성), last_login_at, created_at

**Problem (문제)**
- id, type(MCQ_SINGLE / MCQ_MULTI / OX / SHORT_ANSWER / FILL_BLANK), content(문제 내용, 빈칸 채우기의 경우 `{{blank_n}}` 마커 포함), image_url(업로드된 첨부 이미지 파일의 저장 URL, 선택), reference_text(참조용 지문, 선택), explanation(해설, 선택), blank_reveal_count(빈칸 채우기 전용 - 출제 시 무작위로 노출할 빈칸 개수), status(활성/보관), department_id(FK, 출제 부서), created_by(FK: User), created_at, updated_at

**Tag (태그)**
- id, name(태그명, unique), created_at

**ProblemTag (문제-태그 연결)**
- problem_id(FK), tag_id(FK)

**ProblemChoice (문제 보기, 객관식/OX 전용, 최대 5개)**
- id, problem_id(FK), choice_text, is_correct, display_order

**ProblemAnswer (주관식 정답, 복수 동의어 허용)**
- id, problem_id(FK), answer_text

**ProblemBlank (빈칸 채우기 - 빈칸 후보 정의)**
- id, problem_id(FK), blank_key(예: blank_1), answer_text(해당 빈칸의 정답), display_order

**Attempt (풀이 시도)**
- id, user_id(FK), problem_id(FK), submitted_answer(제출 내용, 빈칸 채우기가 아닌 유형에 사용), is_correct, submitted_at

**AttemptBlankAnswer (빈칸 채우기 시도 상세 - 시도 1건당 노출된 빈칸 수만큼 생성)**
- id, attempt_id(FK), blank_key, submitted_answer, is_correct

**ExcelUploadLog (엑셀 업로드 이력)**
- id, uploaded_by(FK: User), department_id(FK), file_name, total_rows, success_rows, fail_rows, error_detail(JSON), created_at

**AuditLog (감사 로그)**
- id, actor_id(FK: User), action(행위), target_type(대상 유형), target_id(대상 ID), detail(JSON), created_at

### 8.2 기술 스택 제안 (검토 필요)
| 영역 | 제안 |
|---|---|
| 프론트엔드 | React 19 + Vite + Tailwind CSS 4 + react-router-dom + Zustand + react-toastify (기존 프로젝트 의존성 유지) |
| 백엔드 | Spring Boot (Java) 기반 REST API |
| DB | PostgreSQL |
| ORM/영속성 | MyBatis (매퍼 XML 기반) |
| 인증 | 서버 세션(Session Cookie, `httpOnly`) 기반 인증 |
| 엑셀 처리 | Apache POI (`poi-ooxml`) |
| 배포 환경 | 사내 인프라 (구체 사양은 인프라팀과 별도 협의) |

> 백엔드 프레임워크/DB/영속성/인증 방식은 트렌드원 백엔드(`trend_one/backend`)를 참고 아키텍처로 삼아 확정했다. 계층 구조(`controller → service → dao → mapper(XML)`), 공통 응답/에러 처리, CORS 설정, 세션 검증 필터, 엑셀 비동기 업로드 처리 등도 동일한 패턴을 따른다.

## 9. 비기능 요구사항

### 9.1 성능
- 서비스 규모: 중규모 (전사 수백 명, 여러 부서) 기준으로 설계
- 문제 풀이 화면의 문제 제출 후 채점 결과 응답은 체감상 즉시(1초 이내) 처리되어야 한다.
- 엑셀 일괄 업로드는 수백 건 규모의 문제를 처리할 수 있어야 하며, 처리 중 진행 상태(또는 완료 후 결과)를 사용자에게 보여준다.

### 9.2 보안
- 비밀번호는 해시 저장, 평문 저장/전송 금지 (HTTPS 필수)
- 부서 관리자는 API 레벨에서도 자기 부서 외 데이터에 접근할 수 없도록 서버 측 권한 검증을 반드시 수행한다 (프론트엔드 라우팅 차단만으로는 불충분).
- 관리자 계정의 주요 행위(문제 등록/수정/삭제, 계정 생성·수정·비활성화, 부서 변경 등)는 감사 로그 테이블에 누가/언제/무엇을 수행했는지 저장한다.

### 9.3 가용성
- 사내 업무 시간대 접속 집중을 고려하되, 24시간 서비스가 원칙적으로 필요하지는 않음(사내 서비스 특성상 야간 유지보수 가능).

### 9.4 접근성/호환성
- PC는 최신 사내 표준 브라우저(Chrome, Edge 등) 기준 지원
- 모바일은 반응형 웹으로 모바일 브라우저(Chrome, Safari) 기준 지원

| 알림 (이메일/푸시 알림 등) | 이번 범위에 포함하지 않음 |
| 다국어 지원 | 이번 범위에 포함하지 않음 |
