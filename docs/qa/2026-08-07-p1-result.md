## 0. 실행 전 확인한 환경 차이 (중요)

### 0.1 체크리스트 §0.3.1의 QA 계정은 현재 백엔드가 보는 DB에 없다

체크리스트는 QA 계정이 **Docker DB `localhost:5434`** 에 준비돼 있다고 적혀 있으나, 5434는 내려가 있었고(`probank-postgres` 컨테이너 2일 전 종료) 실행 중인 백엔드는 **로컬 `localhost:5432`** 를 보고 있었다. 그 DB에는 부트스트랩 계정 하나와 부서 하나뿐이었다.

```
users:       admin / SUPER_ADMIN / must_change_password=t   (1건)
departments: 본사(HQ)                                        (1건)
```

`admin` / `QaAdmin1234!` 로그인이 실패한 원인이 이것이다. 실제 비밀번호는 부트스트랩 기본값 `changeme1234`였다. 따라서 §0.3.2 절차대로 **QA 데이터를 처음부터 다시 만들고** 진행했다.

| 항목 | 값 |
|---|---|
| 관리자 | `admin` / `QaAdmin1234!` (강제 변경 후 설정) |
| 부서 | `HQ/본사`, `DEV/개발팀`, `SALES/영업팀` (활성) · `OLD/폐지팀`, `SPEC/특수"문자\수정팀ABCDE` (비활성) |
| 계정 | `emp010`(비활성·영업팀), `emp060`(긴 이메일·개발팀), `legacy01`(비활성 부서 소속) 외 엑셀 업로드분 508건 |

### 0.2 SMTP가 포트 25에 있어야 한다 — MailHog 1025로는 계정 생성이 전부 실패한다

체크리스트 §0.1은 MailHog를 `-p 1025:1025`로 띄우고 `MAIL_PORT=1025`를 주라고 안내한다. 그러나 **현재 실행 중인 백엔드(IntelliJ 기동)는 `MAIL_PORT`를 지정하지 않아 기본값 25를 쓰고 있었다.** 그 상태에서 계정을 생성하면 100% 실패한다(아래 D1 참조).

호스트 25번 포트로 MailHog를 추가 기동해 해소했다.

```bash
docker start probank-mailhog                                  # 1025 / 8025 (기존)
docker run -d --name qa-mailhog25 -p 25:1025 -p 8026:8025 mailhog/mailhog   # QA용 추가 기동
```

**QA 중 발송된 메일은 `http://localhost:8026` 에 쌓여 있다.** 이 컨테이너는 QA를 위해 내가 만든 것이므로 필요 없으면 `docker rm -f qa-mailhog25` 로 지우면 된다.

## 1. 발견한 결함

### D1. (Major) 메일 발송 실패 시 관리자가 원인을 전혀 알 수 없다

| 항목 | 내용 |
|---|---|
| 심각도 | **Major** |
| 화면·API | `/admin/users`, `POST /api/admin/users` |
| 재현 절차 | 1. SMTP가 닿지 않는 상태(예: `MAIL_PORT` 기본값 25인데 MailHog는 1025)로 백엔드 기동 2. 계정 생성 폼을 정상 값으로 제출 |
| 기대 | 메일 발송 실패 때문임을 알 수 있는 메시지 (예: "메일 발송에 실패해 계정 생성을 취소했습니다") |
| 실제 | `HTTP 200` + `{"resultCode":-1,"resultMsg":"처리 중 오류가 발생하였습니다."}` — 화면에도 "처리 중 오류가 발생하였습니다."만 표시 |
| 영향 | 설계상 메일 실패 시 계정 생성 전체가 롤백되는데(의도된 동작), 관리자는 **자기가 뭘 잘못했는지·환경 문제인지 구분할 수 없다.** 실제로 이번 QA에서 이 화면 때문에 원인 파악에 시간이 걸렸고, 서버 콘솔을 볼 수 없는 운영자는 영영 알 수 없다 |
| 증거 | `{"resultCode":-1,"resultMsg":"처리 중 오류가 발생하였습니다."}` / MailHog 수신 0건 |

> 참고: 엑셀 업로드 경로는 같은 상황에서 **행별로** "계정 저장 또는 회사 이메일 발송에 실패했습니다."라고 알려 준다(§7.20 통과). 단건 생성 경로만 이 구분이 없다.

### D2. (Minor) 서버 오류인데 HTTP 200으로 응답한다

D1의 응답이 `HTTP 200` + `resultCode:-1`이다. 프론트는 `resultCode`로 분기하므로 화면 동작에는 문제가 없으나, 프록시·모니터링·로그 집계에서 실패가 성공으로 집계된다. 참고로 검증 오류(1000)와 인증 오류(1011)는 올바르게 400을 반환한다.

### D3. (문서 불일치) 계정 수정 모달에 "상태" 필드가 없다

체크리스트 §1.2는 "부서·역할·**상태** Select 변경", §4.2는 "자기 계정 수정 → 상태 INACTIVE → 저장"을 전제한다. 실제 수정 모달에는 **이름 · 회사 이메일 · 부서 · 역할** 4개 필드뿐이고, 상태는 목록 행의 비활성화/활성화 토글로만 바꾼다. 구현 쪽 결함이라기보다 **체크리스트가 실제 화면과 다르다.** §4.2를 수행하려면 절차를 토글 기준으로 고쳐야 한다.

### D4. (오타) 체크리스트 §8.3 액션명

`USER_CREATEㄴD` → `USER_CREATED`. 실제 저장되는 값은 `USER_CREATED`가 맞다.
