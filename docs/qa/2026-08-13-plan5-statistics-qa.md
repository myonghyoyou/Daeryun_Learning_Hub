## 7. 렌더링 검증 (2차 세션, Chrome 재시작 후)

1차 세션에서 브라우저 대상 탭이 사용자 본인이 쓰는 다른 사이트로 바뀌어 중단했었다. Chrome 을 재시작해 5173 전용 탭에서 재개했고, 아래는 그 결과다. **모든 조작은 5173 탭에만 했고 사용자 탭은 건드리지 않았다.**

### 7.1 분포 막대와 제외 안내 (문제 230)

| 확인 | 실측 |
|---|---|
| 막대 색 | `rgb(0, 180, 227)` = `--color-progress-bg` ✅ — 클래스가 실제로 칠해진다 |
| 막대 폭 | 1122 / 797 / 157 / 0 px (Java 7 · Python 5 · HTTP 1 · TCP 0회) — 7:5:1:0 비율과 일치 ✅ |

| **제외 안내 배너** | 실제로 렌더됨 ✅ — 배경 `rgb(255,246,229)` = `--color-warning-bg`, 글자 `rgb(180,101,0)` = `--color-warning-text` |

**한 번도 선택되지 않은 TCP 가 `0회` 로 나온다** ✅ — 빠지면 "아무도 안 고른 보기"라는 신호가 사라진다. 최근 오답도 사람이 읽는 텍스트(`Java, Python, HTTP`)이고, 아무것도 고르지 않은 제출은 `-` 로 표시된다.

### 7.5 콘솔

대시보드 · 목록 · 상세 · 필터 조작 전 구간에서 **오류·경고 0건** ✅
API 응답 중 200 이 아닌 것은 Vite 개발 모듈의 `304 Not Modified` 뿐이며 캐시 동작이지 실패가 아니다.

### 7.6 미검증으로 남은 것 — `Pagination` 렌더

문제가 14건이라 페이지 크기 20 으로는 페이지가 1개뿐이고, `Pagination` 은 `pageCount <= 1` 이면 `null` 을 반환한다(설계대로). 화면에 띄우려면 QA 용 문제를 최소 7건 더 만들어야 하는데, 만들면 통계 목록에 영구히 남는다.

**대신 더 엄격한 검증을 이미 마쳤다** — 페이징이 실제로 위험한 지점은 컴포넌트 렌더가 아니라 **페이지를 넘어가는 정렬**이고, 그것은 §4.2 에서 `size=5` 로 경계 3곳을 확인했다. 컴포넌트 자체는 `ProblemListPage` 가 같은 props(`page`/`totalCount`/`onChange`)로 이미 쓰고 있다.

**모바일 접근 차단**도 미검증이 아니다 — `frontend/src/utils/routing.test.js` 가 `canAccessAdmin({device:"mobile", role:"SUPER_ADMIN"}) === false` 와 `resolveLandingPath(...) === "/solve"` 를 단위 테스트로 고정한다.
