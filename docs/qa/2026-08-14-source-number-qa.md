## Step 1 — 등록 폼의 자동 번호

부서를 고를 때 채워지는 값을 부서를 바꿔 가며 실측했다.

| 조작 | 번호 칸 | 판정 |
|---|---|---|
| 개발팀 선택 (그 부서에 번호 없음) | `1` | ✅ 첫 문제는 1 |
| 개발팀 5번 등록 후 다시 개발팀 | `6` | ✅ 마지막+1 |
| 영업팀으로 변경 | `1` | ✅ 새 부서 기준 |
| 본사로 변경 | `1` | ✅ |
| 다시 개발팀 | `6` | ✅ 이전 부서 값이 남지 않는다 |
| 부서 선택 해제 | `` (빈 값) | ✅ 묵은 번호가 남지 않는다 |

검증 메시지 — 응답 본문을 그대로 확인했다.

| 입력 | 응답 | 판정 |
|---|---|---|
| 비움 | `문항 번호를 입력하세요.` | ✅ |
| `0` | `문항 번호는 1 이상이어야 합니다.` | ✅ |
| `-3` | `문항 번호는 1 이상이어야 합니다.` | ✅ |
| 이미 있는 `5` | `처리 중 오류가 발생하였습니다.` | ❌ **QA-1** |

수정 후 재확인 (백엔드 재기동, 등록·수정 양쪽):

| 경로 | 응답 | 판정 |
|---|---|---|
| 등록 `POST /api/admin/problems?departmentId=862` | 400 · `{"resultCode":1000,"resultMsg":"개발팀 1번은 이미 있습니다. 다른 번호를 입력하세요."}` | ✅ |
| 수정 `PUT /api/admin/problems/1307` | 400 · 같은 메시지 | ✅ |

자동 번호도 API 응답과 대조했다 — `next-source-number` 가 개발팀 `2` · 영업팀 `6` · 본사 `16`
을 돌려주고 화면의 값이 정확히 일치한다(부서 전환 5회, 새로고침 1회 모두 일치).

> 재기동 직후 첫 조회에서 개발팀 값이 한 번 `1` 로 보였다(기대 `2`). 이후 6회 연속 샘플링과
> 부서 전환 매트릭스에서 재현되지 않았고 API 는 계속 `2` 를 돌려줬다. 재기동 직후의 일회성
> 읽기로 판단하되, 재현되면 다시 볼 지점으로 남긴다.

> `문항 번호` 입력칸은 `type="number"` `min="1"` 이지만 DOM 의 `required` 는 `false` 다.
> `required` 는 라벨의 "필수" 배지를 그리는 데만 쓰이고 `<input>` 에 내려가지 않는다.
> 덕분에 브라우저 기본 검증이 폼을 막지 않고 **서버 메시지가 사용자에게 그대로 닿는다.**

## Step 3 — 부서 이동

번호가 겹치는 상황을 일부러 만들었다 — 개발팀 5번, 영업팀 5번.

| 조작 | 결과 | 판정 |
|---|---|---|
| 개발팀 5번 → 영업팀 | HTTP 200 · `{"sourceNumber":6}` | ✅ 충돌 없이 재부여 |
| 화면 번호 칸 | `6` 으로 갱신 | ✅ 묵은 값을 저장할 수 없다 |
| 안내 문구 | `부서를 옮겼습니다. 문항 번호가 1번으로 바뀌었습니다.` | ✅ |

> **QA 이후 최종 리뷰에서 이 경로의 결함이 하나 더 나왔다.** 같은 부서로 "이동"하면
> `findMaxSourceNumber` 가 그 문제 자신의 행까지 세어 `max + 1` 이 원래 번호를 덮어썼다
> (부서 꼬리에 있던 문제는 정확히 1씩 밀린다). 이동 Select 에는 현재 부서도 그대로 들어
> 있고 수정 화면이 현재 부서를 표시하지 않아 관리자가 구분할 수 없었다. 거절하도록 고쳤다 —
> `이미 <부서명> 소속입니다.` QA 는 항상 다른 부서로만 옮겨 봐서 이 경우를 건드리지 않았다.

> 되돌리기(영업팀 → 개발팀)에서 `1` 이 부여됐다. 개발팀에 남은 번호가 없었기 때문이다.
> spec D5 의 "번호를 재사용하지 않는다"는 **보관된 문제**가 번호를 계속 점유한다는 뜻이고,
> 다른 부서로 떠난 문제의 번호는 그 부서에서 실제로 비므로 규칙과 어긋나지 않는다.

## 발견한 결함

### QA-1 (Critical) — 중복 번호 안내가 `처리 중 오류가 발생하였습니다.` 로 나갔다

**증상.** 이미 있는 번호로 저장하면 `{"resultCode":-1,"resultMsg":"처리 중 오류가 발생하였습니다."}`.
기대값은 `개발팀 5번은 이미 있습니다. 다른 번호를 입력하세요.`

**원인.** `duplicateSourceNumber()` 가 안내 문구를 만들려고 `departmentDao.findById()` 를
호출하는데, 이 조회가 **제약을 위반한 INSERT 와 같은 트랜잭션 안**에 있었다. PostgreSQL 은
문장 하나가 실패하면 트랜잭션 전체를 abort 하므로 그 뒤의 SELECT 가 25P02 로 다시 터진다.
psql 로 그대로 재현했다:

```
BEGIN;
INSERT INTO problems (... department_id, source_number ...) VALUES (... 862, 5 ...);
-- ERROR: duplicate key value violates unique constraint "uq_problems_department_source_number"
SELECT name FROM departments WHERE id = 862;
-- ERROR: current transaction is aborted, commands ignored until end of transaction block
```

`DuplicateKeyException` 은 정상적으로 잡혔다. **잡은 뒤 한국어 메시지를 만드는 조회가 도리어
새 예외를 던져** 없애려던 `-1` 을 되살렸다.

**수정.** 부서명을 쓰기 전에 읽어 두고, `duplicateSourceNumber()` 는 DB 를 건드리지 않는다.
`create()` 와 `update()` 가 같은 헬퍼를 쓰므로 한 번의 수정으로 둘 다 해결된다.
등록·수정 한 번에 SELECT 한 번이 더 붙지만 관리자 폼 저장 경로라 부담이 없다.

**재확인.** 백엔드 재기동 후 등록·수정 두 경로 모두 `개발팀 1번은 이미 있습니다. 다른 번호를
입력하세요.` 가 HTTP 400 으로 나온다. Step 1 표에 응답 본문을 그대로 적었다.

**왜 295개 테스트가 못 잡았나.** 서비스 단위 테스트는 DAO 를 목으로 둔다 — 목은 abort 된
트랜잭션을 흉내내지 않으므로 `findById` 가 얌전히 스텁을 돌려준다. DAO 라운드트립 테스트는
예외 **타입**만 단언했고 서비스를 거치지 않았다. **실제 DB 를 통과하는 서비스 경로가 하나도
없었다.** 이 구멍을 메우려고 `@SpringBootTest` 로 실제 `ProblemService.create()` 를 두 번
호출하는 테스트를 넣었고, 수정을 되돌려 두면 한국어 메시지 대신 25P02 로 실패하는 것을
확인했다.

### QA-2 (Important) — 엑셀 템플릿 안내가 12컬럼이었다

화면의 템플릿 안내가 `문제유형 … 태그` 12개만 설명하고 있었다. 안내대로 파일을 만들면
전 행이 `문항 번호는 필수입니다.` 로 실패한다. 이 화면이 곧 파일 형식의 사양이고 653행을
올릴 사람이 보고 따라 하는 문서다. 13번째 컬럼을 헤더·예시 행·설명 문단에 모두 반영했다.

## 이 QA 로 확인되지 않은 것

- **키보드 이동과 포커스 링** — 이번 변경은 배지(정보 표시)만 추가했고 조작 가능한 요소를
  넣지 않았다. `2026-08-12` QA 에서 이미 측정한 값이 그대로 유효하다.
- **`docs/문제은행_엑셀/README.md`** — git 미추적 파일이라 이 브랜치에서 고치지 않았다.
  아직 12컬럼을 설명하므로 **실제 적재 전에 반드시 고쳐야 한다.**
- **722문항 실적재** — 데이터 작업이라 범위 밖(spec §4).
- **부서 마스터 정리** — 현재 부서는 본사·개발팀·영업팀·폐지팀이고 12개 실팀이 아니다.
  사용자가 관리 화면에서 직접 정리한다(spec D1).

## QA 중 만든 데이터

`problems` 에 QA 용 행이 남았다 — 개발팀 1건, 영업팀 1건, 본사 9건(엑셀 5 + 4).
`attempts` 에도 랜덤 23문제 완주 기록이 쌓였다. 통계·이력 화면 검증에 필요했던 것이고
정상 데이터다. 실적재 전에 문제 테이블을 비울 계획이므로(spec D5 근거) 따로 지우지 않았다.
