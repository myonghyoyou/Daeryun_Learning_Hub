## 2. 빈칸 마커 표시 (피드백 2번의 전제)

`{{b1}}` 같은 내부 마커가 학습자에게 그대로 보이던 문제를 표시용 함수로 세 곳에서 함께 고쳤다.

| 화면 | 결과 |
|---|---|
| 골라서 풀기 목록 | `예산의 3요소는 ____, ____, ____ 이다.` ✅ |
| 내 풀이 이력 (PC 표) | `대한민국의 수도는 ____이고, 최대 항구도시는 ____이다.` ✅ |
| 내 풀이 이력 (모바일 카드, 390px) | 동일 ✅ |
| 랜덤 결과 요약 | 동일 ✅ |

**두 마커 형식 모두 처리된다** — 지정 모드가 만드는 `{{b1}}`과 기존 데이터의 `{{blank_1}}`.

각 화면에서 `{{` 문자열을 전수 검색해 **0건**을 확인했다.

**풀이 화면은 침범되지 않았다** — 빈칸이 여전히 입력칸으로 렌더된다. 여기에 표시용 함수가 들어갔다면 학습자가 답을 넣을 수 없게 된다.

## 3. 발견하고 고친 결함 — 방금 제출한 답이 결과에서 사라졌다

### 증상

5문제 세트에서:

1. 1번 풀고 제출 → "다음 문제"
2. 2번 풀고 제출 → 채점 결과 표시
3. **"다음 문제"를 누르지 않고** "그만하고 결과 보기"
4. 결과: **"1문제 중 1개 정답"**, 목록에 1건뿐

**2문제를 제출했는데 1문제로 집계됐다.**

### 원인

`recordResult`를 호출하는 곳이 `handleNext`("다음 문제" 버튼)뿐이었다. 제출만 하고 넘어가지 않은 답은 세션에 기록되지 않는데, 종료 처리가 그 상태를 그대로 받았다.

함수 주석에는 "이미 제출한 결과는 지키면서"라고 적혀 있었지만 **대기 중인 제출 하나를 놓쳤다.**

채점 자체는 서버(`attempts`)에 저장돼 이력 화면에는 남으므로 데이터 유실은 아니다. 그러나 세트 요약이 사실과 달랐고, 버튼이 약속한 것을 지키지 못했다.

### 수정 (`189bad9`)

종료 처리가 대기 중인 제출을 **먼저 반영한 뒤** 세트를 끝낸다. 그리고 "보여줄 결과가 없으면 홈으로" 판정을 **반영 후 index**로 한다 — 반영 전 값으로 판정하면 1번을 풀자마자 그만둔 사용자가 방금 푼 문제를 통째로 잃는다.

### 재검증 — 네 경계 케이스

| 상황 | 버튼 문구 | 도착 | 집계 |
|---|---|---|---|
| 아무것도 제출 안 하고 종료 | **학습 홈으로** | `/solve` | — |
| 1번 제출 직후 종료 | 그만하고 결과 보기 | `/solve/random/result` | **1문제 중 0개 정답** |
| 1번→다음→2번 제출 직후 종료 | 그만하고 결과 보기 | `/solve/random/result` | **2문제 중 0개 정답** |
| 로드 실패 화면에서 나가기 | 문제를 못 불러온 상태라 대기 제출이 항상 없어 동작 불변 | | |

세 번째가 원래 결함의 재현 순서다. 목록에도 두 문제가 모두 나온다.
