## 0. 시작 전 준비

### 0.1 실행 순서

세 가지가 순서대로 떠 있어야 한다.

```bash
# 1) DB + 메일 서버
docker compose up -d

# 2) 백엔드 — MAIL_PORT를 반드시 준다 (아래 함정 참조)
cd backend
MAIL_PORT=1025 ./gradlew bootRun --args='--spring.profiles.active=dev'

# 3) 프론트엔드 — 반드시 5173 포트여야 한다 (아래 함정 참조)
cd frontend
npm run dev
```

### 0.2 반드시 알고 시작할 함정 3가지

**① 프론트가 5173이 아니면 로그인 자체가 안 된다.**
백엔드 CORS가 `http://localhost:5173`만 허용한다. 5173이 이미 점유돼 Vite가 5174로 뜨면, 로그인 시 화면에는 **"로그인에 실패했습니다."**만 나오고 실제 원인(`403 Invalid CORS request`)은 보이지 않는다. 비밀번호 문제로 착각하기 쉽다.
→ 시작 전에 `netstat -ano | findstr :5173`으로 비어 있는지 확인할 것.

**② 백엔드를 재기동하면 로그인이 풀린다.**
세션이 메모리에 있어서 재기동 시 전부 날아간다. 갑자기 로그인 화면으로 튕기면 이걸 의심할 것.

**③ 이전 백엔드가 살아 있을 수 있다.**
Gradle을 Ctrl+C로 끊어도 자식 Java 프로세스가 8080을 잡고 남는 경우가 있다. 그러면 새 백엔드는 `PortInUseException`으로 죽고 **옛날 코드가 계속 응답한다** — 고친 게 반영 안 된 것처럼 보인다.
→ `netstat -ano | findstr :8080`으로 PID를 찾아 `taskkill /PID <번호> /F`.

SELECT a.id, a.problem_id, a.submitted_answer, a.is_correct, a.submitted_at
FROM attempts a JOIN users u ON u.id=a.user_id
WHERE u.employee_no='emp001' ORDER BY a.id DESC LIMIT 10;"

## 6. 이상 입력 — 화면을 우회한 직접 호출

F12 → Console에서 아래를 붙여넣어 실행한다. 로그인된 세션이 그대로 쓰인다.

**6.1 없는 문제 풀기**

```js
await (await fetch('/api/problems/999999', {credentials:'include'})).text()
```
기대: 오류 응답(정상 데이터 아님).

**6.2 보관된 문제 풀기** — 아래 ID는 보관된 문제로 바꿔 넣는다

```js
await (await fetch('/api/problems/255', {credentials:'include'})).text()
```
기대: **거부**. 보관된 문제는 풀 수 없어야 한다.

**6.3 빈칸을 요구 개수와 다르게 제출**

```js
await (await fetch('/api/problems/254/attempts', {method:'POST',
  headers:{'Content-Type':'application/json'}, credentials:'include',
  body: JSON.stringify({blankAnswers:[{blankKey:'b1',submittedAnswer:'편성'},{blankKey:'b2',submittedAnswer:'집행'}]})
})).text()
```
기대: **거부** — 노출 개수가 1인데 2개를 냈으므로 "제출한 빈칸 개수가 올바르지 않습니다".

**6.4 존재하지 않는 빈칸 키로 제출**

```js
await (await fetch('/api/problems/254/attempts', {method:'POST',
  headers:{'Content-Type':'application/json'}, credentials:'include',
  body: JSON.stringify({blankAnswers:[{blankKey:'b9',submittedAnswer:'아무거나'}]})
})).text()
```
기대: **거부**.

**6.5 서버가 지정하지 않은 빈칸에 답하기** ← 결과를 반드시 기록할 것

상세 조회를 해서 이번에 풀어야 할 빈칸이 `b1`이라고 나왔는데, `b2`에 답을 내 본다.

```js
await (await fetch('/api/problems/254/attempts', {method:'POST',
  headers:{'Content-Type':'application/json'}, credentials:'include',
  body: JSON.stringify({blankAnswers:[{blankKey:'b2',submittedAnswer:'집행'}]})
})).text()
```

**현재 코드는 이걸 통과시킬 가능성이 높다.** 서버는 "개수가 맞는가", "존재하는 키인가"만 보고 "이 사용자에게 지정했던 그 빈칸인가"는 검사하지 않는다. 통과한다면 학습자가 매번 새로고침해서 쉬운 빈칸만 골라 풀 수 있다는 뜻이다.
→ **통과하면 결함으로 기록.** 심각도는 "학습 효과 저해" 수준이며 데이터 손상은 아니다.

**6.6 다른 사람 이력 훔쳐보기**

```js
await (await fetch('/api/attempts/me', {credentials:'include'})).text()
```
기대: 로그인한 본인 것만. 다른 사용자 데이터가 섞여 있으면 **중대 결함**.

## 8. 결과 정리

### 8.1 마치고 나서

```bash
# 프론트엔드 테스트
cd frontend && npm test        # 226개 통과 기대

# 백엔드 테스트
cd backend && ./gradlew test   # 224개 통과 기대
```

### 8.2 결함 기록 양식

발견한 것은 `docs/qa/` 아래에 아래 형식으로 남긴다.

```md
### D1 — 한 줄 요약

- **심각도:** Critical / Important / Minor
- **재현 절차:** 1) … 2) … 3) …
- **기대:** …
- **실제:** …
- **증거:** 화면 캡처 / API 응답 / DB 조회 결과
- **영향:** 누가 어떤 상황에서 무엇을 겪는가
```

**심각도 기준**

| 등급 | 판단 기준 |
|---|---|
| Critical | 정답이 사전 노출된다 / 남의 데이터가 보인다 / 채점이 틀린다 / 이력이 유실된다 |
| Important | 특정 유형이 안 풀린다 / 이력 표시가 틀리다 / 보관 문제가 풀린다 |
| Minor | 마커가 그대로 보인다 / 문구가 어색하다 / 정렬이 이상하다 |

### 8.3 QA 중 만든 데이터

풀이 이력(`attempts`)은 계속 쌓인다. 정리하려면:

```bash
docker exec -e PGPASSWORD=probank_dev probank-postgres psql -U probank -d probank_dev -c "
DELETE FROM attempt_blank_answers WHERE attempt_id IN
  (SELECT a.id FROM attempts a JOIN users u ON u.id=a.user_id WHERE u.employee_no='emp001');
DELETE FROM attempts WHERE user_id=(SELECT id FROM users WHERE employee_no='emp001');"
```

> 지우기 전에 3장(이력 화면) 검증을 먼저 끝낼 것.
