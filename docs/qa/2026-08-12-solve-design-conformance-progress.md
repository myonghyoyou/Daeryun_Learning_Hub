### 이 브랜치에서 반복된 실패 유형

**"코드는 그럴듯한데 CSS가 안 나오거나 다른 값으로 폴백되는" 문제가 네 번 나왔다.**

1. `line-clamp-${n}` 문자열 조립 → Tailwind가 클래스를 못 찾음
2. 음수 `outline-offset` → 생성 여부 불확실
3. `sr-only` → 이미 Tailwind가 제공하는데 손으로 중복 정의
4. `line-clamp-1` → 매핑에 없어 3으로 폴백

**전부 빌드 산출물(`frontend/dist/assets/*.css`) grep으로만 잡혔다.** 재개 후에도 CSS 클래스를 새로 쓸 때는 반드시 빌드 산출물에서 확인할 것.

### 환경 준비 (`docs/qa/2026-08-12-plan4-solve-qa-manual.md` §0 참조)

```bash
docker compose up -d
cd backend && MAIL_PORT=1025 ./gradlew bootRun --args='--spring.profiles.active=dev'
cd frontend && npm run dev
```

**함정 3가지:**
1. **프론트가 5173이 아니면 로그인 자체가 안 된다.** 백엔드 CORS가 5173만 허용한다. 5174로 뜨면 화면에는 "로그인에 실패했습니다"만 나오고 진짜 원인(`403 Invalid CORS request`)은 안 보인다
2. **이 브랜치는 백엔드 무변경이라 백엔드 재기동은 불필요하다.** 다만 이미 떠 있는 백엔드가 옛 코드일 수 있으니 `/api/problems`가 응답하는지 확인
3. Gradle을 Ctrl+C로 끊어도 자식 Java 프로세스가 8080에 남는다. `netstat -ano | findstr :8080` → `taskkill /PID <번호> /F`
