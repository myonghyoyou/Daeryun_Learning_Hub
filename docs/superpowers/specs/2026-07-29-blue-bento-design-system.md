# Blue Bento Learning 디자인 시스템 명세

## 1. 문서 목적

이 문서는 문제 은행 Hub의 선택된 디자인 방향인 **Blue Bento Learning**을 실제 화면과 컴포넌트 구현에 일관되게 적용하기 위한 디자인 시스템 기준서다.

적용 범위는 PRD와 5개 구현 Plan에 정의된 다음 표면 전체다.

- 인증: 로그인, 최초 비밀번호 변경
- 직원용 학습: 학습 홈, 문제 목록, 문제 풀이, 본인 풀이 이력
- 관리자용 문제 운영: 문제 목록, 문제 등록·수정, 문제 엑셀 업로드
- 관리자용 조직 운영: 부서 관리, 계정 관리, 계정 엑셀 업로드
- 관리자용 통계: 문제별 정답률 목록, 통계 상세

이 문서는 시각 스타일만 정의하지 않는다. 정보 위계, 컴포넌트 상태, 반응형 규칙, 접근성, 화면별 밀도까지 함께 정의하여 디자인과 프론트엔드 구현의 기준점으로 사용한다.

## 2. 디자인 방향

### 2.1 한 문장 정의

**신뢰감 있는 Blue 계열을 기반으로, 학습 행동을 가장 먼저 보이게 하는 목적성 있는 Bento 업무 도구.**

### 2.2 핵심 원칙

1. **학습 행동 우선**: 직원 화면에서는 “이어서 학습하기”, “문제 풀기”가 첫 시선에 들어와야 한다.
2. **정보 덩어리의 명확한 구획**: Bento 레이아웃을 사용하되 모든 요소를 카드로 만들지 않는다. 독립된 목적이 있는 영역만 Surface로 묶는다.
3. **브랜드 색상은 행동과 상태에 집중**: Blue는 주요 행동, Aqua는 진행·선택·강조, Dark Blue는 구조와 텍스트에 사용한다.
4. **업무 도구의 밀도 유지**: 관리자 화면은 표와 필터를 우선하고, 장식성 여백이나 과도한 라운딩을 사용하지 않는다.
5. **평면적이고 조용한 표면**: 글래스모피즘, 과도한 그림자, 그라디언트, 네온 효과는 기본 시스템에서 사용하지 않는다.
6. **색상만으로 상태를 전달하지 않음**: 상태명, 아이콘, 텍스트를 항상 함께 제공한다.
7. **한 화면 한 가지 주 행동**: 화면마다 Primary Action은 원칙적으로 하나만 둔다.

### 2.3 시각 언어

- 표면: White 중심, Cool Gray 배경, 얇은 경계선
- 강조: 단단한 Blue 블록과 제한적인 Aqua 포인트
- 모서리: 6~12px의 작은 반경. 16px 이상은 특별한 Hero 카드에만 허용
- 아이콘: Phosphor 계열 선형 아이콘, 기본 18px
- 레이아웃: 8pt 기반 간격, 데스크톱 12-column grid, 모바일 단일 열
- 그림자: Surface의 계층을 보조하는 수준으로만 사용

## 3. 색상 토큰

### 3.1 브랜드 원색과 디지털 UI 색상 구분

첨부된 브랜드 가이드의 인쇄·로고 기준색과 현재 UI 시안에서 사용하는 디지털 UI 색상은 구분한다. 로고 원본을 임의로 재색상하지 않으며, 화면 UI에는 디지털 토큰을 사용한다.

| 역할 | 브랜드 가이드 기준 | 디지털 UI 토큰 | 용도 |
|---|---:|---:|---|
| HHIC Dark Blue | `#1E4B9B` | `#005CA9` | 주요 버튼, 활성 내비게이션, 핵심 숫자 |
| HHIC Blue | `#195FA0` | `#008BD2` | 링크, 보조 버튼, 진행 상태 |
| HHIC Aqua | `#32A0BE` | `#00B4E3` | 진행 바, 선택 포인트, 포커스, 학습 강조 |

디지털 UI 토큰은 현재 선택된 Blue Bento 시안과 프로토타입에 사용된 값이다. 향후 실제 로고 SVG/PNG가 제공되면 로고에는 브랜드 가이드 기준을 사용하고, UI는 위 디지털 값으로 유지한다.

### 3.2 원시 색상 토큰

```css
:root {
  --color-brand-dark: #005CA9;
  --color-brand-blue: #008BD2;
  --color-brand-aqua: #00B4E3;

  --color-ink-strong: #102B4C;
  --color-ink-default: #52667D;
  --color-ink-muted: #75849A;
  --color-ink-subtle: #9AAABD;

  --color-surface-page: #F6F9FC;
  --color-surface-default: #FFFFFF;
  --color-surface-subtle: #F9FBFC;
  --color-surface-blue: #EEF7FD;
  --color-surface-aqua: #E8FAFF;

  --color-line-default: #E3EAF2;
  --color-line-strong: #CDD9E4;
  --color-focus: #00B4E3;
}
```

### 3.3 시맨틱 색상 토큰

시맨틱 토큰을 컴포넌트에서 직접 사용한다. `brand-blue`를 오류 상태에 직접 쓰는 식으로 원시 색상을 의미 없이 사용하지 않는다.

| 시맨틱 토큰 | 값 | 사용 규칙 |
|---|---:|---|
| `action-primary-bg` | `#005CA9` | 화면당 핵심 제출·등록·시작 버튼 |
| `action-primary-hover` | `#004D8E` | Primary hover |
| `action-secondary-text` | `#005CA9` | 보조 버튼과 텍스트 링크 |
| `selection-bg` | `#EAF7FD` | 선택된 메뉴, 행, 필터 |
| `progress-bg` | `#00B4E3` | 진행률과 학습 진척 |
| `info-text` | `#007BB7` | 공개, 안내, 정보 |
| `info-bg` | `#EAF8FD` | 정보 배경 |
| `success-text` | `#087C59` | 정답, 완료, 성공 |
| `success-bg` | `#F0FCF6` | 성공 피드백 배경 |
| `warning-text` | `#B46500` | 검토중, 중간 위험 |
| `warning-bg` | `#FFF6E5` | 경고 피드백 배경 |
| `danger-text` | `#C94155` | 오류, 삭제, 오답 |
| `danger-bg` | `#FFF0F2` | 오류 피드백 배경 |

### 3.4 사용 비율

- Neutral surface/text/line: 약 75~85%
- Dark Blue/Blue 구조 및 행동: 약 10~20%
- Aqua 및 semantic accent: 약 5% 이내
- Aqua를 전체 배경, 대형 장식, 긴 문단의 강조색으로 사용하지 않는다.

## 4. 타이포그래피 토큰

### 4.1 글꼴

- 기본: `Noto Sans KR`
- 시스템 대체: `Apple SD Gothic Neo`, `Malgun Gothic`, `sans-serif`
- 한 화면에서 글꼴 종류는 하나만 사용한다.
- 숫자와 영문도 같은 계열을 사용하되, 표의 숫자는 `font-variant-numeric: tabular-nums`를 적용한다.

```css
:root {
  --font-family-sans: "Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif;
}
```

### 4.2 타입 스케일

| 토큰 | 크기 / 행간 | 굵기 | 적용 |
|---|---|---:|---|
| `type-display` | 28px / 36px | 800 | 로그인·학습 홈의 환영 문구 등 제한적 사용 |
| `type-page-title` | 24px / 32px | 800 | 페이지 제목 |
| `type-section-title` | 17px / 24px | 700 | Surface 제목 |
| `type-card-title` | 15px / 22px | 700 | 학습 카드, 추천 세트 |
| `type-body` | 14px / 22px | 400~500 | 일반 설명, 문제 본문 |
| `type-body-small` | 12px / 18px | 400~600 | 보조 설명, 표 본문 |
| `type-label` | 11px / 16px | 700 | 필드 라벨, 상태, 필터명 |
| `type-caption` | 10px / 14px | 500~600 | 메타 정보, 보조 숫자 |

규칙:

- 본문과 문제 내용은 14px 미만으로 낮추지 않는다.
- 표가 조밀해지는 경우에도 12px을 최소값으로 한다.
- 10px은 날짜·보조 메타 등 의미가 약한 정보에만 사용한다.
- 제목은 `letter-spacing: -0.04em`을 기준으로 하되, 본문에는 적용하지 않는다.
- 긴 문제 제목은 2줄까지 허용하고, 표의 제목 열은 ellipsis 처리 후 상세 화면에서 전체 내용을 제공한다.

## 5. 간격·크기·형태 토큰

### 5.1 간격

8pt 기반을 기본으로 하며, 4px은 아이콘과 텍스트 사이의 미세 조정에만 사용한다.

| 토큰 | 값 | 주요 사용 |
|---|---:|---|
| `space-1` | 4px | 아이콘-텍스트 간격 |
| `space-2` | 8px | 태그 간격, 작은 필드 간격 |
| `space-3` | 12px | 행 내부 패딩, 버튼 간격 |
| `space-4` | 16px | 필드 그룹, 카드 내부 기본 간격 |
| `space-5` | 20px | Surface 내부 패딩 |
| `space-6` | 24px | 화면 섹션 간격 |
| `space-8` | 32px | 페이지 상단·주요 영역 간격 |
| `space-10` | 40px | 대형 섹션 분리 |
| `space-12` | 48px | 로그인·집중형 화면의 큰 여백 |
| `space-16` | 64px | 제한적인 Hero 영역 |

### 5.2 레이아웃 크기

| 토큰 | 데스크톱 | 모바일 |
|---|---:|---:|
| `layout-sidebar-width` | 220px | 전체 상단 내비게이션으로 변경 |
| `layout-topbar-height` | 76px | 88px 이내, 검색창은 다음 행 허용 |
| `layout-content-max` | 1440px | 100% |
| `layout-page-padding-x` | 28px | 14~16px |
| `layout-section-gap` | 18px | 14px |
| `control-height-sm` | 32px | 34px |
| `control-height-md` | 38px | 40px |
| `control-height-lg` | 44px | 44px |
| `table-row-height` | 48~52px | 카드형 목록으로 전환 |

### 5.3 반경

| 토큰 | 값 | 주요 사용 |
|---|---:|---|
| `radius-xs` | 4px | 상태 배지, 표 태그 |
| `radius-sm` | 6px | 버튼, 입력창, Select |
| `radius-md` | 8px | 선택지, 작은 패널 |
| `radius-lg` | 10px | 일반 Surface, 학습 카드 |
| `radius-xl` | 12px | 집중형 Hero 카드 |
| `radius-pill` | 999px | 진행 바, 원형 상태 |

16px 이상 반경과 둥근 전체 앱 컨테이너는 사용하지 않는다. Bento의 현대적인 인상은 반경보다 정렬·간격·색상 블록으로 만든다.

### 5.4 테두리와 그림자

```css
:root {
  --border-default: 1px solid #E3EAF2;
  --border-strong: 1px solid #CDD9E4;
  --shadow-surface: 0 8px 24px rgba(21, 65, 108, 0.06);
  --shadow-raised: 0 10px 22px rgba(0, 92, 169, 0.12);
}
```

- 기본 Surface에는 `shadow-surface`를 사용하거나 그림자를 생략한다.
- 버튼 hover, Toast, 선택된 학습 카드처럼 계층이 분명한 경우만 `shadow-raised`를 사용한다.
- 그림자와 테두리를 동시에 강하게 사용하지 않는다.
- 그라디언트는 기본 토큰에 정의하지 않는다.

## 6. 아이콘 규칙

- 아이콘 라이브러리: `@phosphor-icons/react`
- 기본 아이콘 크기: 18px
- Topbar/주요 액션: 20px
- Sidebar 아이콘 타일: 18px 아이콘 + 27px 타일
- 버튼 내부 아이콘과 텍스트 사이: 6~8px
- 선형 아이콘은 기본 `regular`, 활성·완료 상태는 `fill` 또는 `duotone`을 사용한다.
- 아이콘만 있는 버튼에는 반드시 `aria-label`을 제공한다.
- 아이콘으로 텍스트를 대체하지 않는다. 예: 삭제 아이콘만 제공하지 말고 Tooltip 또는 접근 가능한 이름을 제공한다.

## 7. 컴포넌트 명세

### 7.1 AppShell

구조:

```text
AppShell
├── SidebarNav
└── AppMain
    ├── Topbar
    └── PageContent
```

규칙:

- 데스크톱: `220px sidebar + flexible content`.
- Topbar는 페이지 콘텐츠와 분리된 흰색 표면으로 유지한다.
- PageContent는 최대 1440px, 좌우 28px 패딩을 사용한다.
- 모바일: 관리자 라우트는 PRD 규칙에 따라 문제 풀이로 리다이렉트하고, 직원용 화면만 반응형으로 제공한다.

### 7.2 SidebarNav

구성:

- 로고 영역
- `주요 메뉴` 그룹
- `관리 메뉴` 그룹
- 하단 학습 팁·설정·고객센터

상태:

| 상태 | 표현 |
|---|---|
| Default | 투명 배경, muted 텍스트, 27px 아이콘 타일 |
| Hover | `#F0F7FB` 배경, Dark Blue 텍스트 |
| Active | `#EAF7FD` 배경, Blue 아이콘, 좌측 2px Aqua 인디케이터 |
| Disabled | 텍스트·아이콘 40% opacity, 클릭 불가 |
|

규칙:

- 활성 메뉴에 진한 파란색 전체 블록과 강한 그림자를 사용하지 않는다.
- 메뉴 라벨은 12px, 그룹 라벨은 9px으로 제한한다.
- 메뉴 행 높이는 38px, 그룹 사이 간격은 18px이다.
- 확장 메뉴의 Caret은 우측 정렬하며, 열린 상태는 180도 회전한다.

### 7.3 Topbar

구성:

- 현재 사용자 환영 문구
- 전역 문제 검색
- 알림 아이콘
- 사용자 프로필

규칙:

- 높이 76px, 배경 White, 하단 1px line.
- 검색창은 최대 330px, 높이 38px.
- 환영 문구는 17px, 보조 문구는 12px.
- 알림·프로필은 보조 행동이므로 Primary 버튼으로 표현하지 않는다.

### 7.4 Button

| 종류 | 배경 | 텍스트 | 용도 |
|---|---|---|---|
| Primary | Dark Blue | White | 등록, 제출, 학습 시작, 조회 |
| Secondary | White | Dark Blue | 초기화, 상세 보기, 취소 |
| Tertiary | Transparent | Blue | 더보기, 전체 보기, 보조 링크 |
| Destructive | Danger | White | 삭제, 비활성화 확인 |

사이즈:

- `sm`: 32px, 좌우 12px, 11px
- `md`: 38px, 좌우 16px, 12px
- `lg`: 44px, 좌우 18px, 13px

상태:

- Hover: 배경을 한 단계 어둡게 하거나 surface를 한 단계 밝게 한다.
- Focus: 3px Aqua outline, 2px offset.
- Disabled: opacity 45%, cursor not-allowed.
- Loading: 버튼 폭을 유지하고 spinner와 “처리 중”을 표시한다.

### 7.5 Input / Search / Select

- 기본 높이 38px, 모바일 40px.
- 좌우 패딩 12px, radius 6px.
- 라벨은 컨트롤 위에 11px bold로 둔다.
- Placeholder는 실제 값처럼 보이지 않도록 `#9AAABD`를 사용한다.
- 오류 상태는 Border Danger + 오류 메시지로 처리한다.
- 검색창은 돋보기 아이콘을 좌측에 두고, 검색어 초기화 버튼이 있으면 우측에 둔다.
- Select의 placeholder와 선택값을 구분한다.

### 7.6 TagChip

태그는 분류를 위한 인터랙션이며, 상태 배지와 혼용하지 않는다.

| 상태 | 배경 | 테두리/텍스트 |
|---|---|---|
| Default | White | `#DCE6F0` / Muted |
| Hover | `#F1F8FC` | Blue |
| Selected | `#EAF7FD` | Blue |
| Removable | Selected + X 아이콘 | X 버튼에 aria-label |

태그 이름은 한 줄로 유지하고, 화면 폭이 부족하면 가로 스크롤 또는 “+N”으로 축약한다.

### 7.7 Surface / Panel

용도별로 세 가지 계층만 사용한다.

1. `Surface Default`: White + line + subtle shadow. 독립 기능 영역.
2. `Surface Subtle`: `#F9FBFC`. Surface 내부의 보조 영역.
3. `Surface Brand`: Dark Blue 또는 Blue. 학습 시작과 같은 핵심 행동 영역.

카드 안에 카드를 중첩하지 않는다. 단, 하나의 Surface 안에 정보 그룹을 line으로 나누는 것은 허용한다.

### 7.8 Progress / Metric

- 숫자와 진행 바를 함께 사용한다.
- 진행률은 Blue/Aqua로 표시하고, 완료·진행 중·남은 항목의 범례를 함께 제공한다.
- 숫자만으로 의미를 전달하지 않고 `전체 진도율`, `남은 문제`처럼 라벨을 둔다.
- 원형 그래프보다 수평 진행 바를 기본으로 한다. 원형 그래프는 통계 요약 카드 등 제한적으로 사용한다.

### 7.9 StatusBadge / Difficulty

상태와 난이도는 서로 다른 컴포넌트다.

- `StatusBadge`: 공개, 비공개, 검토중, 활성, 비활성
- `Difficulty`: 상, 중, 하

난이도 색상:

- 상: Danger 계열 점 + “상” 텍스트
- 중: Warning 계열 점 + “중” 텍스트
- 하: Success 계열 점 + “하” 텍스트

점 색상만으로 구분하지 않고 반드시 텍스트를 함께 표시한다.

### 7.10 DataTable

- Header: `#F9FBFC`, 40~44px
- Row: 48~52px, 하단 1px line
- Body text: 12px, 핵심 제목은 Ink Strong
- Hover: `#F1F8FC`
- Selected: `#EAF7FD` + 좌측 또는 checkbox 상태
- 숫자 열: 오른쪽 정렬 또는 고정 폭
- 제목 열: 최대 2줄 또는 ellipsis
- 행 액션은 마지막 열에 배치하고, 세로 점 아이콘만 있을 경우 accessible name을 제공한다.
- 모바일에서는 관리자 테이블을 억지로 축소하지 않고 라우팅 규칙으로 접근을 제한한다. 직원 이력은 카드형 목록으로 바꾼다.

### 7.11 QuizChoice

- 최소 높이 56px, 모바일 60px 이상.
- 보기 번호 또는 유형 아이콘을 왼쪽에 배치한다.
- 선택 상태: Aqua border + `#F0FBFD` 배경.
- 정답 결과: Success 배경과 설명.
- 오답 결과: Danger 배경과 정답·해설을 함께 표시.
- 제출 전에는 Primary 버튼을 disabled 처리하되, disabled 이유를 시각적으로만 전달하지 않는다.

### 7.12 Feedback / Toast / Empty

- Toast는 화면 우측 하단, 모바일에서는 하단 12px inset.
- 성공·오류 Toast에 아이콘, 요약, 닫기 버튼을 제공한다.
- 빈 상태에는 “데이터가 없습니다”만 표시하지 않고 다음 행동을 제공한다.
- 로딩 상태는 콘텐츠 위치를 유지하는 skeleton 또는 명확한 progress indicator를 사용한다.
- 오류 상태는 재시도 버튼과 사용자에게 필요한 오류 원인을 함께 표시한다.

## 8. 화면별 적용 규칙

### 8.1 로그인 / 비밀번호 변경

대상 Plan: 01 Foundation & Auth

- 로그인 화면은 PC와 모바일에서 동일한 컴포넌트 구조를 사용하되, 화면 크기에 따라 여백과 정렬만 변경한다.
- 배경은 `surface-page`를 사용하고, 전체 화면을 큰 카드 하나로 감싸지 않는다. White Surface는 폼 영역에만 제한적으로 사용한다.
- PC 기준 콘텐츠 폭은 400px, 폼 영역의 최대 폭은 440px이다. 화면 수직 중앙보다 약간 위에 배치하여 브라우저·키보드 환경에서도 주 내용이 잘리지 않게 한다.
- 모바일 기준 좌우 padding은 20px, 최소 viewport 320px을 지원한다. Safe Area가 있는 기기에서는 `env(safe-area-inset-top/bottom)`을 추가한다.
- 로고 lockup → 제목 → 안내 문구 → 사번 입력 → 비밀번호 입력 → 로그인 버튼 → 보조 안내 순서다.
- 로고 lockup은 화면 상단의 장식이 아니라 제품 식별 영역이며, 실제 제공된 로고 자산을 사용한다. 로고를 CSS 도형이나 텍스트 조합으로 재현하지 않는다.
- 제목은 `type-page-title`, 안내 문구는 `type-body-small`, 필드 라벨은 `type-label`을 사용한다.
- 입력 필드는 한 열, Primary 버튼은 폼 전체 폭으로 제공한다.
- 인증 식별자는 사번이며, 회사 이메일·공개 회원가입·아이디 찾기 화면은 MVP 범위에 넣지 않는다.
- 비밀번호 입력은 표시/숨김 토글을 제공하고, 토글 버튼은 44px hit area와 `aria-label`을 가진다.
- 오류는 필드 아래에 즉시 표시하고 Toast만으로 끝내지 않는다. 오류가 있어도 입력값과 포커스는 가능한 한 보존한다.

#### 8.1.1 로그인 상태별 규칙

| 상태 | 화면 표현 | 주 행동 |
|---|---|---|
| 초기 | 빈 입력, Primary 활성 | 사번 입력에 자동 포커스 |
| 입력 중 | Focus ring, 입력값 유지 | 로그인 |
| 유효성 오류 | 해당 필드 Danger border + 오류 문구 | 오류 필드 수정 |
| 인증 실패 | 폼 상단 안내 + 사번 필드 포커스 유지 | 다시 로그인 |
| 처리 중 | 버튼 폭 유지, spinner + “로그인 중” | 중복 제출 차단 |
| 비활성 계정 | 폼 상단 오류 안내, 고객센터 안내 | 관리자 문의 |
| 잠금 | 잠금 사유와 재시도 가능 시점 안내 | 잠금 해제 후 재시도 |
| 성공 | 별도 성공 화면 없이 역할·기기별 랜딩 | 서버 응답 후 이동 |

- 비밀번호 오류를 “사번이 존재하지 않음”처럼 계정 존재 여부가 노출되는 문구로 구분하지 않는다.
- 5회 이상 실패로 계정이 잠긴 경우 재시도 버튼을 제공하지 않고 잠금 안내를 우선한다.
- 로그인 요청 중 브라우저 뒤로가기·새로고침으로 상태가 깨지지 않도록 submit 상태를 관리한다.

#### 8.1.2 최초 비밀번호 변경

- 로그인 화면과 동일한 AppShell을 사용하지 않고, 인증 전용 단순 레이아웃을 유지한다.
- 제목은 “비밀번호 변경”, 설명은 “최초 로그인 시 비밀번호를 변경해야 합니다.”로 명확히 표시한다.
- 필드 순서: 새 비밀번호 → 새 비밀번호 확인.
- 비밀번호 규칙은 입력 전부터 보이고, 충족 여부는 아이콘과 텍스트로 표시한다.
- 불일치 상태는 확인 필드 아래에 즉시 표시한다.
- 저장 중에는 버튼을 잠그고, 성공 시 역할·기기별 랜딩 화면으로 이동한다.

#### 8.1.3 로그인 후 라우팅 피드백

로그인 화면 자체에서는 역할에 따른 메뉴를 미리 노출하지 않는다. 서버 세션 응답과 기기 판별 결과에 따라 다음 규칙을 적용한다.

| 기기·역할 | 이동 | 로그인 후 UI |
|---|---|---|
| PC·총괄/부서 관리자 | 관리자 대시보드 | 관리자 Sidebar와 학습 전환 메뉴 노출 |
| PC·직원 | 직원 학습 홈 | 관리자 메뉴 비노출 |
| 모바일·모든 역할 | 직원 학습 홈 | 직원 모바일 내비게이션만 노출 |

- 모바일에서 관리자 URL을 직접 입력하면 로그인 화면으로 되돌리지 않고 직원 학습 홈으로 이동한다.
- 세션 만료로 로그인 화면에 재진입하는 경우 “세션이 만료되었습니다. 다시 로그인해 주세요.”를 폼 상단에 표시한다.

#### 8.1.4 모바일 로그인 화면

```text
Safe Area Top
Logo lockup
로그인 제목 / 안내 문구
사번 입력
비밀번호 입력 + 표시 토글
로그인 버튼
인증 오류 또는 세션 안내
Safe Area Bottom
```

- 모바일 로그인 폼은 화면 폭의 100%가 아니라 좌우 20px inset을 가진다.
- 로고 lockup은 상단 32px 여백 이후 배치하고, 제목과 24px 이상 간격을 둔다.
- 입력 컨트롤은 시각 높이 44px, 터치 hit area 48px을 기준으로 한다.
- 키보드가 열리면 화면 전체를 축소하지 않고 문서가 세로로 스크롤되도록 한다.
- 비밀번호 필드가 키보드 위로 가려지면 해당 필드가 보이도록 자동 스크롤한다.
- 로그인 버튼은 키보드가 열린 상태에서도 접근할 수 있어야 하며, `Enter` 키로 제출할 수 있다.
- 모바일에서는 자동 확대를 방지하기 위해 입력 글자 크기를 16px 미만으로 낮추지 않는다.
- 오류 메시지는 Toast가 아니라 입력 영역 아래의 inline message를 우선한다.
- 네트워크 오류는 “인터넷 연결을 확인한 후 다시 시도해 주세요.”로 안내하고 재시도 버튼을 제공한다.
- 로그인 성공 후 화면 전환 중에는 짧은 loading 상태를 표시하고, 관리자 메뉴를 잠깐 노출하지 않는다.

### 8.2 직원 학습 홈 `/solve`

대상 Plan: 04 Quiz Solving

데스크톱 12-column 기준:

```text
Row 1: ContinueLearning 8열 | ProgressPanel 4열
Row 2: RecommendedSet 8열 | RecentActivity 4열
Row 3: RoutinePanel 12열
```

- 첫 번째 Primary Action은 `학습 이어가기`.

- 학습 현황은 숫자·진행 바·범례를 한 그룹으로 제공한다.
- 추천 문제 세트는 icon/제목/설명/태그/주 행동 순서다.
- 활동 목록은 3개만 우선 노출하고 전체 보기는 링크로 제공한다.
- 모바일은 단일 열로 전환한다.

라우팅 기준:

- `/solve`: 직원 학습 홈
- `/solve/problems`: 문제 목록
- `/solve/:id`: 문제 풀이 상세
- `/solve/history`: 본인 풀이 이력

Plan 4의 프론트엔드 라우팅도 이 기준에 맞춰 정렬했다. 학습 홈 안에는 추천 문제와 문제 목록 진입 링크를 제공하고, 문제 목록은 `/solve/problems`에서 독립적으로 제공한다.

### 8.3 문제 목록 `/solve/problems`

- 직원 화면의 문제 목록은 학습 목적의 간결한 목록으로 구성한다.
- 필터는 과목·단원·태그를 우선 제공하고, 상세 필터는 보조 영역으로 둔다.
- 문제 카드/행에는 제목, 문제 유형, 태그, 난이도만 먼저 보인다.
- 등록일은 직원 화면의 기본 필터에 노출하지 않고, 필요한 경우 상세 필터로 제공한다.
- 클릭 영역은 행 전체이며, hover와 focus 상태를 동일하게 제공한다.

### 8.4 문제 풀이 `/solve/:id`

- 문제 본문을 화면의 가장 넓은 영역에 둔다.
- 문제 번호·유형·진행률은 본문 위에 작게 배치한다.
- 보기 간 세로 간격은 10~12px, 보기 최소 높이는 56px이다.
- 제출 후 결과를 같은 화면에서 보여주며, 사용자가 정답·해설을 찾기 위해 이동하지 않도록 한다.
- 모바일에서는 선택지와 Primary 제출 버튼이 화면 폭을 사용한다.
- 제한 시간·시험 종료·응시 기간 UI를 넣지 않는다. PRD는 자유 연습·복습 모드다.

#### 8.4.1 PC 문제 목록

- PC 문제 목록은 직원용 학습 화면이며 관리자 DataTable을 그대로 복제하지 않는다.
- 최대 콘텐츠 폭은 1120px, 좌우 padding은 28px, 목록과 보조 패널의 비율은 8:4를 기준으로 한다.
- 상단에는 페이지 제목·내 풀이 이력 링크·문제 검색을 둔다.
- 필터는 과목·단원·태그를 먼저 노출하고, 상세 필터는 Secondary 버튼으로 연다.
- 문제 항목은 하나의 Surface 안에서 row separator로 구분한다. 각 항목을 별도 카드로 만들지 않는다.
- 행 정보 순서는 문제 유형 → 문제 제목 → 과목·단원 → 난이도·태그다.
- 직원 화면에는 내부 ID, 등록자, 관리자용 공개 상태를 기본 노출하지 않는다.
- 행 전체가 링크이며, Enter와 Space로도 `/solve/:id`에 진입할 수 있어야 한다.
- 결과 없음은 검색어와 함께 “조건에 맞는 문제가 없습니다.”를 표시하고 필터 초기화 행동을 제공한다.

#### 8.4.2 PC 문제 상세·풀이

데스크톱 12-column 기준:

```text
상단 메타·이전 이동
문제 본문 8열 | 학습 진행·문제 정보 4열
보기 또는 답안 입력 8열
해설·결과 8열
하단 이전/다음/제출 영역
```

- 문제 본문은 최대 720px line length를 유지한다.
- 참조 지문은 문제 본문 위에 `Surface Subtle`로 표시하고, 긴 지문은 접기/펼치기를 제공한다.
- 문제 이미지는 원본 비율을 유지하고, 최대 콘텐츠 폭을 넘지 않는다. 대체 텍스트를 필수로 제공한다.
- 객관식·OX는 `QuizChoice`, 주관식은 44px 입력 필드, 빈칸 채우기는 본문 내 입력 필드로 표현한다.
- 객관식 다중 선택은 선택 상태에 checkbox 의미를 추가하고, 단일 선택과 시각적으로 구분한다.
- 빈칸 채우기는 노출된 빈칸 수와 현재 입력 상태를 함께 표시한다.
- Primary Action은 `답안 제출` 하나로 제한한다. 이전·다음은 Tertiary 또는 Secondary로 처리한다.
- 제출 후 정답 결과는 Success Surface, 오답 결과는 Danger Surface로 표시하고 정답·해설을 같은 콘텐츠 흐름에 둔다.
- 결과가 표시된 뒤 Primary Action은 `다시 풀기` 또는 `다음 문제`로 바뀐다.

#### 8.4.3 PC 풀이 상태

| 상태 | 화면 처리 |
|---|---|
| 초기 로딩 | 문제 본문·보기 위치를 유지하는 skeleton |
| 로드 실패 | 문제 영역 ErrorState + 재시도 |
| 답안 미선택 | 제출 버튼 disabled, 필요한 입력 안내 |
| 제출 중 | 선택지 잠금, 버튼 spinner, 중복 제출 차단 |
| 정답 | Success feedback + 정답·해설 |
| 오답 | Danger feedback + 정답·해설 + 다시 풀기 |
| 저장 실패 | 결과를 확정하지 않고 재시도 안내 |
| 이전/다음 로딩 | 현재 콘텐츠 유지 + 전환 영역만 loading |

### 8.5 본인 풀이 이력 `/solve/history`

- 데스크톱: DataTable.
- 모바일: 문제 제목·시도 일시·정답 여부를 세로 카드로 변환.
- 정답/오답은 Success/Danger 색상과 텍스트를 함께 표시한다.
- 제출 답안은 상세 보기에서 확인하며, 긴 답안은 접기/펼치기를 제공한다.
- PC 테이블 컬럼은 문제 제목, 문제 유형, 시도 일시, 정답 여부, 제출 답안 보기 순서다.
- 최신 시도순을 기본 정렬로 하며, 정답 여부 필터는 보조 필터로 제공한다.
- 시도 이력이 없으면 빈 상태 설명과 `문제 풀러 가기` Primary/Tertiary 행동을 제공한다.
- 상세 답안은 행 확장 또는 Modal 중 하나로 일관되게 선택한다. 화면마다 다른 방식을 사용하지 않는다.

### 8.6 관리자 공통 Shell·대시보드 `/admin`

대상 Plan: 01 Foundation & Auth, 02~05 관리자 화면 공통

#### 8.6.1 관리자 Shell

- 관리자 PC 화면은 `220px Sidebar + 76px Topbar + PageContent` 구조다.
- 직원용 학습 Shell과 관리자 Shell은 Sidebar 메뉴와 랜딩 화면을 분리한다.
- 관리자 Sidebar에는 다음 순서로 메뉴를 제공한다.

```text
대시보드
문제 관리
  문제 목록
  문제 등록
  문제 엑셀 일괄 등록
학습 현황 / 통계
부서 관리 (총괄 관리자만)
계정 관리 (총괄 관리자만)
```

- 총괄 관리자와 부서 관리자의 공통 메뉴는 문제 관리·통계이며, 부서·계정 관리는 총괄 관리자에게만 노출한다.
- 부서 관리자는 Sidebar에서 권한 없는 메뉴를 숨기며, 비활성화된 메뉴를 보여주지 않는다.
- 관리자 Topbar에는 현재 역할·부서·세션 상태를 확인할 수 있는 프로필 영역을 둔다.
- 학습 화면으로 이동하는 메뉴를 Topbar 또는 Sidebar 하단에 제공한다.
- 활성 메뉴는 직원 Shell과 동일한 컴팩트 규칙을 사용하며, 진한 Blue 전체 블록 대신 `selection-bg`와 2px Aqua 인디케이터를 사용한다.
- 관리자 화면에서는 Bento 카드를 장식적으로 반복하지 않고, 목록·필터·작업 영역을 우선한다.

#### 8.6.2 관리자 대시보드

- `/admin`은 로그인한 관리자에게 첫 진입 화면으로 제공한다.
- 상단에는 “관리자 대시보드” 제목, 현재 부서 범위, 최근 갱신 상태를 표시한다.
- 첫 행은 문제 수·검토 필요 문제·전체 시도 수·평균 정답률의 4개 compact metric으로 구성한다.
- 두 번째 행은 정답률이 낮은 문제 목록과 최근 문제 등록 활동을 7:5 비율로 배치한다.
- 총괄 관리자에게만 부서 선택 필터를 제공하고, 부서 관리자는 자기 부서로 고정한다.
- 관리자 대시보드의 Primary Action은 `문제 등록`으로 제한한다.
- 통계 수치는 숫자만 표시하지 않고 기준 기간·부서 범위를 함께 표시한다.
- 데이터가 없으면 빈 그래프 대신 설명과 다음 행동을 제공한다.

#### 8.6.3 관리자 공통 상태

- 로딩: Header와 필터 위치는 유지하고 표·metric 영역만 skeleton 처리한다.
- 권한 없음: ErrorState에 접근 가능한 메뉴 또는 이전 화면 이동을 제공한다.
- 세션 만료: 현재 작업 중인 입력을 잃지 않도록 안내 후 로그인으로 이동한다.
- 저장 성공: Toast + 변경된 행 또는 상세 영역의 즉시 반영.
- 저장 실패: 서버 오류와 검증 오류를 구분하여 표시한다.
- 삭제·보관·비활성화: 확인 Modal에서 대상명·영향·취소·확정 버튼을 명시한다.
- 부분 성공: 엑셀 업로드처럼 성공과 실패가 함께 발생하는 경우 결과 요약과 오류 목록을 각각 제공한다.

### 8.7 관리자 문제 목록 `/admin/problems`

대상 Plan: 03 Problem Bank Management

- 관리자 화면은 데스크톱 전용 밀도를 유지한다.
- 페이지 헤더: 제목·설명·우측 `문제 등록` Primary 버튼.
- FilterPanel은 Surface 하나로 묶되, 필터마다 별도 카드로 만들지 않는다.

### 8.8 문제 등록·수정 `/admin/problems/new`, `/admin/problems/:id/edit`

- 필수 필드는 label에 `필수`를 텍스트로 표시하며 색상만으로 구분하지 않는다.
- 저장은 화면의 유일한 Primary Action.
- 삭제·보관은 저장 버튼과 시각적으로 분리하고 확인 Modal을 거친다.
- 이미지 첨부는 파일명·크기·삭제 상태를 표시하며, 업로드 중 progress를 제공한다.

## 9. 반응형 규칙

### 9.1 브레이크포인트

- `mobile`: `< 768px`
- `desktop-compact`: `768px ~ 1199px`
- `desktop`: `≥ 1200px`

PRD 규칙에 따라 모바일에서 관리자 라우트는 문제 풀이 화면으로 리다이렉트한다. 따라서 관리자 화면을 모바일에서 억지로 재배치하지 않는다.

### 9.2 직원 모바일

- 모바일 앱 셸의 상단 내비게이션 높이는 56px로 고정한다. 65px 이상으로 키우지 않는다.
- 상단 내비게이션에는 로고 또는 홈, 학습, 문제, 이력 등 최대 4개의 핵심 아이콘만 노출한다. 텍스트 메뉴는 공간이 충분한 경우에만 보조로 표시한다.
- 현재 위치는 Aqua 하단 인디케이터 또는 `selection-bg`로 표시하며, 진한 Blue 전체 블록을 사용하지 않는다.
- 전역 검색은 Topbar에 억지로 넣지 않고 문제 목록 화면의 필터 영역으로 이동한다.
- 페이지 좌우 padding은 16px, 섹션 간격은 14px, Surface 내부 padding은 16px이다.
- 카드 grid는 1열로 전환한다. 카드 안에서 다시 카드가 중첩되지 않도록 한다.
- 학습 카드 내부 콘텐츠 순서는 제목 → 현재 단원 → 진도 → Primary 버튼으로 유지한다.
- 큰 숫자나 장식 영역보다 문제 본문과 선택지를 우선한다.

#### 9.2.1 모바일 학습 홈

화면 순서:

```text
MobileHeader 56px
Greeting / 페이지 제목
ContinueLearning
ProgressPanel
RecommendedProblemSet
RecentActivity
RoutinePanel
```

- 첫 화면 상단 600px 안에 “이어서 학습하기”와 Primary `학습 이어가기`가 들어와야 한다.
- ContinueLearning은 화면 폭 전체를 사용하되, 카드 높이는 콘텐츠에 따라 190~230px 범위로 제한한다.
- ProgressPanel은 숫자·수평 진행 바·범례를 세로로 배치한다. 데스크톱의 2열 metric을 모바일에서 1열 또는 2개 compact row로 바꾼다.
- RecommendedProblemSet은 제목·태그·문제 수·`문제 풀기`만 우선 표시하고 설명은 2줄에서 자른다.
- 최근 활동은 최대 3개를 노출하고, 각 행의 터치 영역은 44px 이상으로 만든다.
- RoutinePanel은 2열 또는 가로 스크롤이 가능한 compact metric으로 제공하되, 화면을 가리는 대형 그래프는 사용하지 않는다.

#### 9.2.2 모바일 문제 목록

- `/solve/problems`는 검색·태그·과목 필터를 상단에 두고 결과를 단일 열 목록으로 표시한다.
- 필터 버튼을 누르면 Bottom Sheet 또는 화면 내 펼침 영역으로 필터를 표시한다. 데스크톱의 5열 필터를 그대로 축소하지 않는다.
- 등록일은 기본 화면에서 숨기고 “상세 필터” 안에 둔다. 시작일·종료일은 세로 입력으로 배치한다.
- 문제 항목은 제목 → 유형·난이도 → 태그 순서이며, 등록자·상태·내부 ID는 직원 모바일 목록에서 숨긴다.
- 항목 전체가 링크이며, 터치 시 `/solve/:id`로 이동한다.
- 검색 결과 없음, 네트워크 오류, 로딩 상태를 각각 별도 화면 상태로 제공한다.

#### 9.2.3 모바일 문제 풀이

- `/solve/:id`는 문제 번호·진행률·문제 유형을 상단에 고정하고, 문제 본문은 그 아래에 둔다.
- 문제 본문은 18~22px, 행간 1.6을 기준으로 하며 한 줄이 너무 길어지지 않게 한다.
- 참조 지문은 기본 4~6줄까지 표시하고, 긴 지문은 `전체 보기`로 펼친다.
- 문제 이미지는 화면 폭 100%를 넘지 않으며, 확대가 필요한 경우 별도 이미지 보기 Modal을 사용한다.
- 이미지가 로드되지 않으면 대체 텍스트와 재시도 또는 문제 본문을 가리지 않는 ErrorState를 표시한다.
- 선택지는 세로 1열, 최소 시각 높이 56px, 터치 hit area는 60px 이상으로 한다.
- 빈칸 채우기는 본문 안의 입력을 최소 44px 높이로 만들고, 빈칸 번호·현재 입력값·오류 상태를 함께 표시한다.
- 빈칸이 여러 개이면 다음 빈칸으로 이동하는 순서를 자연스럽게 유지하고, 키보드가 열린 상태에서 제출 버튼이 가려지지 않게 한다.
- 제출 버튼은 화면 하단에 고정할 수 있으며, 고정 시 `padding-bottom: 88px`을 확보한다.
- 제출 전에는 선택 상태, 제출 중에는 spinner, 제출 후에는 정답/오답 feedback을 같은 화면에 표시한다.
- 해설이 긴 경우 “해설 보기” 접기/펼치기를 제공하며, 결과가 선택지를 밀어내더라도 제출 버튼을 잃지 않게 한다.
- 이전 문제·다음 문제는 하단 제출 영역과 시각적으로 분리한다.

#### 9.2.4 모바일 풀이 이력

- `/solve/history`는 테이블 대신 카드형 목록을 사용한다.
- 카드에는 문제 제목, 시도 일시, 정답 여부를 우선 표시하고 제출 답안은 펼친 상세에서 제공한다.
- 정답/오답은 텍스트와 아이콘을 함께 사용한다.
- 긴 제목은 2줄까지 보여주고, 전체 제목은 상세 또는 펼침으로 확인할 수 있다.

#### 9.2.5 모바일 공통 상태·기기 규칙

- 초기 로딩은 화면 구조를 유지하는 skeleton을 사용한다.
- 오류는 화면 상단 안내 또는 콘텐츠 영역의 ErrorState로 제공하고, 재시도 버튼을 둔다.
- Bottom Sheet가 열리면 배경 스크롤을 잠그고, 닫기 버튼·바깥 영역·Esc로 닫을 수 있게 한다.
- 세로 스크롤을 기본으로 하며, 가로 스크롤은 필터 칩이나 매우 긴 데이터에만 제한적으로 사용한다.
- 관리자 역할이라도 `<768px`에서 관리자 Sidebar와 관리자 URL을 보여주지 않는다.
- 브라우저 폭이 PC에서 모바일로 바뀌면 관리자 화면을 즉시 직원 학습 홈으로 리다이렉트한다.
- 모바일 컨트롤의 시각 높이가 40px인 경우에도 외곽 interactive hit area는 최소 44px을 확보한다. Button·QuizChoice·Bottom Sheet action은 시각 높이 자체를 44px 이상으로 한다.

### 9.3 관리자 데스크톱

- 테이블은 최소 폭을 보장하고, 화면이 좁아지면 콘텐츠 영역에 수평 스크롤을 둔다.
- 필터가 5열에 들어가지 않는 경우 3열로 줄이되, 컨트롤의 높이는 유지한다.
- 상세 폼은 2열에서 1열로 줄일 수 있지만 관리자 모바일 라우팅 제한은 유지한다.

### 9.4 화면별 Design QA 기준

구현 후 다음 viewport와 상태를 기준으로 화면 캡처를 비교한다.

| 영역 | 기준 viewport | 필수 상태 |
|---|---|---|
| 로그인 PC | 1440 × 1024 | 초기, 오류, 로딩 |
| 로그인 모바일 | 390 × 844 | 초기, 키보드 입력, 오류, 비밀번호 표시 |
| 직원 학습 홈 PC | 1440 × 1024 | 기본, 데이터 없음 |
| 직원 학습 홈 모바일 | 390 × 844 | 기본, 긴 제목, 스크롤 |
| 문제 목록 PC | 1440 × 1024 | 기본, 태그 필터, 등록일 필터, 결과 없음 |
| 문제 목록 모바일 | 390 × 844 | 필터 열림, 결과 없음, 오류 |
| 문제 풀이 PC | 1440 × 1024 | 객관식 선택 전·후, 제출 중, 정답, 오답 |
| 문제 풀이 모바일 | 390 × 844 | 선택지, 고정 제출, 긴 해설, 빈칸 입력 |
| 관리자 문제 목록 | 1440 × 1024 | 기본, 로딩, 권한 범위, 빈 결과 |
| 관리자 등록/수정 | 1440 × 1024 | 기본, 검증 오류, 저장 중, 저장 성공 |
| 관리자 엑셀 업로드 | 1440 × 1024 | 파일 선택 전, 업로드 중, 부분 성공, 전체 실패 |
| 관리자 통계 | 1440 × 1024 | 기본, 시도 0건, 상세, 부서 필터 |

모든 QA 캡처에서 다음을 확인한다.

- 메뉴·타이포그래피·간격·토큰 색상이 디자인 시스템 값과 일치하는가
- Primary Action이 화면당 하나로 명확한가
- 44px hit area와 키보드 포커스가 유지되는가
- 로딩·오류·빈 상태에서 레이아웃이 갑자기 이동하지 않는가
- 관리자와 직원의 메뉴·권한 범위가 잘못 노출되지 않는가
- 모바일에서 고정 제출 영역이 콘텐츠·Safe Area·키보드와 겹치지 않는가

## 10. 접근성 규칙

- 본문 대비는 WCAG AA를 목표로 한다.
- 색상으로만 공개/검토중/정답/오답을 구분하지 않는다.
- 모든 입력에는 visible label 또는 `aria-label`이 있어야 한다.
- 포커스는 3px Aqua outline과 2px offset으로 표시한다.
- 키보드만으로 Sidebar, Filter, Table row action, Quiz choice, Submit을 순서대로 조작할 수 있어야 한다.
- Modal이 열리면 포커스를 내부로 이동하고 닫힌 뒤 원래 트리거로 반환한다.
- 표의 헤더와 데이터 관계를 `<th scope>`로 제공한다.
- 로딩·성공·오류 상태는 `aria-live="polite"` 영역을 사용한다.
- 아이콘-only 버튼은 이름과 목적을 명확히 제공한다.
- 모션은 150~200ms를 기본으로 하며, `prefers-reduced-motion: reduce`에서는 전환을 최소화한다.

## 12. Tailwind/CSS 토큰 매핑

Tailwind CSS 4를 사용하되, 화면에서 임의의 `blue-600`, `gray-500`을 반복하지 않고 디자인 토큰을 참조한다.

```css
@theme {
  --color-brand-dark: #005CA9;
  --color-brand-blue: #008BD2;
  --color-brand-aqua: #00B4E3;
  --color-ink-strong: #102B4C;
  --color-ink-default: #52667D;
  --color-surface-page: #F6F9FC;
  --color-line-default: #E3EAF2;
  --radius-control: 6px;
  --radius-surface: 10px;
  --shadow-surface: 0 8px 24px rgba(21, 65, 108, 0.06);
}
```

예시:

```jsx
<button className="h-10 rounded-control bg-brand-dark px-4 text-sm font-semibold text-white">
  문제 등록
</button>
```

금지 예시:

```jsx
// 임의 색상과 크기를 화면마다 직접 작성하지 않는다.
<button className="rounded bg-blue-600 px-4 py-2 text-white">문제 등록</button>
```

## 13. 화면 구현 완료 기준

각 화면은 다음 기준을 충족해야 한다.

- 디자인 토큰 외의 임의 색상·간격·반경이 없다.
- Primary Action이 한눈에 식별된다.
- Hover, Focus, Disabled, Loading, Success, Error 상태가 정의되어 있다.
- 데스크톱 기준 선택된 Blue Bento의 정보 밀도와 계층을 유지한다.
- 직원 화면은 768px 미만에서 문제 풀이가 가능하다.
- 관리자 화면은 PRD의 데스크톱 전제와 권한 범위를 유지한다.
- 태그·등록일 필터는 문제 목록 화면에서 실제 조작 가능하다.
- 정답·오답·공개·검토중·난이도 상태는 텍스트와 색상을 함께 사용한다.
- 키보드 포커스와 스크린 리더 이름이 누락되지 않는다.
- 화면 캡처 기반 Design QA에서 타이포그래피, 간격, 색상, 아이콘, 카피를 확인한다.

## 14. 적용 우선순위

1. `tokens.css`와 Global font/spacing/radius 정의
2. AppShell, SidebarNav, Topbar의 컴팩트 밀도 적용
3. Button, Input, Select, TagChip, Surface, StatusBadge 공통화
4. 직원 학습 홈의 Bento 레이아웃 적용
5. 문제 목록·등록·업로드 화면 적용
6. 문제 풀이·이력 화면 적용
7. 부서·계정·통계 화면 적용
8. 반응형·접근성·상태별 Design QA

이 순서를 지켜야 화면마다 서로 다른 Blue, radius, shadow가 생기는 것을 방지할 수 있다.
